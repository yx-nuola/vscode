- 降低 ECharts option 的体积和构建开销。

- 清理残留注释与死代码，提升可维护性。

## 4. 方案 A：option 数据瘦身

### 4.1 现状与问题

当前每个数据点被拼成一个混合对象（chart-option-builder.ts:128-133）：

```ts
data: series.points.map((point) => ({
  value: [point.x, point.y],
  point,                       // 含完整原始行 raw（Record<string,string>）
  deviceValue: series.deviceValue,
  groupName: series.groupName,
})),
```

问题：

1. option 中每点都携带整行原始数据引用，序列化/对比开销大。
2. `deviceValue` / `groupName` 字段在 tooltip 中实际未使用（`formatTooltip` 只读 `point.raw`）。
3. `point.raw`（types.ts:45）只有 `formatTooltip` 一处使用（chart-option-builder.ts:149/151），是唯一的引用入口。
4. echarts 对纯数组数据会走更快的内部处理路径（typed array），混合对象没有这个收益。

### 4.2 目标格式（已实施）

每个 series 的 `data` 改为三元组纯数组：

```ts
data: series.points.map((point) => [point.x, point.y, point.rowIndex]),
```

- `[0]` = x，`[1]` = y，供 echarts 直接绘图。
- `[2]` = `rowIndex`（`rows` 数组下标），tooltip 凭它反查原始行。
- 不再需要 `point`、`deviceValue`、`groupName`。

### 4.3 行反查：直接使用 rows 数组下标，不建索引

tooltip 需要从数据三元组的 `[2]` 反查原始行。

**实现**：`ChartPoint.rowIndex` 直接取该行在 `rows` 数组中的下标（`group-builder.ts` 用 `rows.entries()` 的下标），tooltip 反查即 `rows[data[2]]`：

```ts
// ChartPoint
{ x: number; y: number; rowIndex: number }

// formatTooltip
const row = Array.isArray(data) ? rows[data[2]] : undefined;
```

O(1) 且零额外内存。解析阶段用 `skipEmptyLines: 'greedy'` 去掉空行，`rows` 只含真实数据行，因此下标连续、无空洞。

**早期方案对比（已废弃）**：曾设计 `RowIndexMap`（`buildRowIndexMap` 把行按下标展开成数组）。由于 `rowIndex` 就是 `rows` 数组下标，直接 `rows[data[2]]` 即可，`RowIndexMap` 成为多余一层，已随 header:true 改造删除（`utils/row-index.ts`、`utils/row-index.test.ts` 一并删除）。

### 4.4 内存量化（N = 行数）

方案 A 之后每点 data 为三元组纯数组（`[x, y, rowIndex]`），tooltip 反查直接使用 `parsedData.rows`（原始行只此一份，不复制），不新增任何索引结构：

| 结构 | 每项开销 | 1万行 | 10万行 |
|---|---|---|---|
| 方案 A 之前的每点包装对象 | ~80-120 B/点 | ~1 MB | ~10 MB |
| 方案 A 之后的 data 三元组 | 3 number/点 | 远小于前者 | 远小于前者 |

结论：方案 A 不增加内存，反而把 option 内的每点包装对象移除；`rows` 数组本身是 `ParsedCsvData` 的既有数据，反查只是数组下标取值。

### 4.5 改动映射（已实施）

| 文件 | 改动 |
|---|---|
| `LineChartWorkbench.tsx` | 直接透传 `parsedData.rows` 给 `ChartContent`，不再构建 rowIndex |
| `components/ChartContent.tsx` | 新增 `rows` prop 并透传给 `ChartCard`，不再依赖 rowIndex |
| `components/ChartCard.tsx` | 新增 `rows` prop；`buildChartOption` 改为 `buildChartOption(displaySeries, columns, xColumn, yColumn, rows)` |
| `utils/chart-option-builder.ts` | `series.data` 改为三元组；`formatTooltip` 按 `data[2]` 查 `rows`；顺带完成方案 C |
| `types.ts` | `ChartPoint.raw`、`sourceRowIndex`、`CsvColumn.unit` 移除，`ChartPoint` 改为 `x/y/rowIndex`（数组下标） |

### 4.6 formatTooltip 改造（已实施）

改造后签名与逻辑：

```ts
interface TooltipParameter {
  data?: [number, number, number];
  marker?: string;
  seriesName?: string;
}

function formatTooltip(
  parameter: unknown,
  columns: CsvColumn[],
  rows: ParsedCsvRow[],
): string {
  const tooltipParameter = Array.isArray(parameter)
    ? (parameter[0] as TooltipParameter | undefined)
    : (parameter as TooltipParameter);
  const data = tooltipParameter?.data;
  const row = Array.isArray(data) ? rows[data[2]] : undefined;

  if (!row) {
    return '';
  }

  const detailRows = columns.map((column) => {
    const value = row[column.rawName];
    return `<div><span>${escapeHtml(column.displayName)}:</span> ${escapeHtml(value ?? '')}</div>`;
  });

  return [
    `<strong>${tooltipParameter?.marker ?? ''}${escapeHtml(tooltipParameter?.seriesName ?? '')}</strong>`,
    ...detailRows,
  ].join('');
}
```

注意：

- 保留 `Array.isArray(parameter)` 分支，兼容 `trigger: 'item'` 时 formatter 收到单对象/数组的差异。
- merge 模式下大组信息仍通过 `seriesName`（`deviceValue / series.name` 前缀）展示，不依赖 data 内嵌字段。
- `buildChartOption` 的 useMemo 依赖需补上 `rows`，避免 tooltip 闭包拿到旧行数组。

### 4.7 兼容与风险

- 分组业务逻辑（group-builder.ts）不动，结果只影响 option 序列化格式和 tooltip 取数路径。
- 现有测试（group-builder.test.ts、csv-parser.test.ts、axis-range.test.ts、chart-style.test.ts、sample-data.test.ts）不受影响。
- 若新增对 `buildChartOption` 的测试，需要同步断言新 data 格式。
- `rowIndex` 即 `rows` 数组下标，天然唯一且连续，是可靠的反查键。

## 5. 方案 B1：图表实例增量更新

### 5.1 现状与问题

`hooks/useLazyECharts.ts:8-51` 的 effect 依赖 `[option]`：option 一旦变化，cleanup 先 `chart.dispose()`，再重新 `echarts.init` + 重建懒加载观察器。

问题：

- 每次配置变化（Draw / 切换分图合并图）都销毁重建，产生初始化闪烁。
- 反复 init/dispose 有 GC 与重排成本。
- 与《需求.md》bug #12（3.csv 切换分图/合并图异常、感觉没销毁实例）的体验问题相关。

### 5.2 设计：初始化与更新分离

用 `chartRef` 持有实例，用 `optionRef` 兜住"未初始化时 option 已更新"的闭包过期问题：

```ts
export function useLazyECharts(option: EChartsOption) {
  const containerRef = useRef<HTMLDivElement | null>(null);
  const chartRef = useRef<echarts.EChartsType | null>(null);
  const optionRef = useRef(option);
  optionRef.current = option;

  // 初始化：只在挂载时执行一次（含懒加载）
  useEffect(() => {
    const container = containerRef.current;

    if (!container) {
      return;
    }

    let resizeObserver: ResizeObserver | null = null;
    let intersectionObserver: IntersectionObserver | null = null;

    const initializeChart = (): void => {
      if (chartRef.current) {
        return;
      }

      chartRef.current = echarts.init(container);
      chartRef.current.setOption(optionRef.current, true);
      resizeObserver = new ResizeObserver(() => chartRef.current?.resize());
      resizeObserver.observe(container);
    };

    if (typeof IntersectionObserver === 'undefined') {
      initializeChart();
    } else {
      intersectionObserver = new IntersectionObserver(
        (entries) => {
          if (entries.some((entry) => entry.isIntersecting)) {
            initializeChart();
            intersectionObserver?.disconnect();
            intersectionObserver = null;
          }
        },
        { rootMargin: '400px 0px' },
      );
      intersectionObserver.observe(container);
    }

    return () => {
      intersectionObserver?.disconnect();
      resizeObserver?.disconnect();
      chartRef.current?.dispose();
      chartRef.current = null;
    };
  }, []);

  // 更新：option 变化时增量替换数据
  useEffect(() => {
    chartRef.current?.setOption(option, true);
  }, [option]);

  return containerRef;
}
```

要点：

- 初始化 effect 依赖为空数组，只在挂载时建立观察器和实例，卸载时统一清理。
- 更新 effect 复用实例调 `setOption(option, true)`；`true`（notMerge）保证序列整体替换、不留陈旧 series。
- 初始化时用 `optionRef.current` 而非闭包 option，避免"先变 option 后懒加载初始化"用旧数据。
- 配合 B2 后，标题编辑只改 `titles` 状态，option 引用不变（useMemo 依赖不含 title），不会触发任何 setOption。

### 5.3 风险

- 若未来需要保留用户的交互状态（如 `magicType` 切过的 line/bar），`setOption` 的 `true` 会重置它。当前需求下全量替换是预期行为；如要保留，把第二个参数改为默认 merge 并测试。

## 6. 方案 B2：修复标题编辑导致图表重建

### 6.1 现状与问题（本次代码更新引入的回归）

`components/ChartContent.tsx`：

```tsx
<ChartCard
  ...
  key={mergedTitle}                       // line 103，merge 模式
/>
...
<ChartCard
  ...
  key={titles[group.id] ?? group.title}   // line 110，split 模式
/>
```

问题：

- 标题编辑只改 `titles` 状态，但 `key` 也随之变化 → React 把整张 `ChartCard` 卸载重建 → 图表重新 init/dispose，出现闪烁、缩放与曲线状态丢失。
- Split 模式下若两个大组 `title` 相同（同一 device-id 的多个区间，见《开发文档.md》§3.1），`key` 会碰撞，产生 React 警告与错误复用。
- 直接违背《开发文档.md》§12"修改显示配置后，只要大组 ID 未变化，自定义标题不丢失"的预期。

### 6.2 改动

- merge：去掉 `key={mergedTitle}`（标题本来就是 prop，无需 key）。
- split：`key` 改用稳定的 `group.id`（`big-group-${index}-${deviceValue}`，`bigGroupIndex` 保证唯一）。

```tsx
{config.drawMode === 'merge' ? (
  <ChartCard
    chartId="__merged__"
    title={mergedTitle}
    groups={result.groups}
    columns={columns}
    xColumn={config.xColumn}
    yColumn={config.yColumn}
    isMerged
    onTitleChange={onTitleChange}
  />
) : (
  result.groups.map((group) => (
    <ChartCard
      chartId={group.id}
      title={titles[group.id] ?? group.title}
      key={group.id}
      groups={[group]}
      columns={columns}
      xColumn={config.xColumn}
      yColumn={config.yColumn}
      isMerged={false}
      onTitleChange={onTitleChange}
    />
  ))
)}
```

- 配合 B1，标题编辑后图表零重建；option 引用不变，不会触发 setOption。

## 9. 方案 E：可选微优化

### 9.1 移除 `ChartPoint.raw`（已实施）

- `data-adapter.ts` 重写为仅保留 `findDeviceColumn` + `normalizeName`；同时删除无引用的 `findColumnByDisplayName`、`findCurrentColumn`。
- `useCsvUpload.ts` 改为 `parseCsv(text)` 直连，不再调用 `addVirtualDeviceId`。
- `sample-data.test.ts` 移除 `addVirtualDeviceId` 调用，并把 RESET/SET 用例 `deviceColumn` 修正为 `DeviceID`。
- `demoData/polyline/SET.csv` 的 `DeviceID` 列原本整列为空（分组会被全部判为无效、输出 0 组），已按 `WL-BL`（如 `121-5`）补全，共 15 个大组。

保留 `findDeviceColumn`：分组仍需要按配置列名规范化识别（如 `device-id`、`Device ID`）。

### 9.4 buildChartOption 双重遍历

`chart-option-builder.ts:50-55` 对 x / y 各 `flatMap` 一次收集极值。可改为单次遍历同时统计 x / y 范围，减少一次全量遍历。收益小，可做可不做。

### 9.5 分组缓存现状确认

`LineChartWorkbench.tsx:25-31` 的 `chartResult` 已用 `useMemo` 且依赖为 `[appliedConfig, parsedData]`，满足《开发文档.md》§16"只有文件或绘图配置变化时重新执行分组"。无需额外优化。

## 10. 改造前后数据流对比

改造前：

```text
parseCsv -> rows: {sourceRowIndex, values: Record}
  -> buildChartGroups -> groups[].series[].points[] (ChartPoint 含 raw)
    -> createDisplaySeries -> DisplaySeries[]（含 deviceValue/groupName）
      -> buildChartOption -> data: [{value:[x,y], point, deviceValue, groupName}, ...]
        -> tooltip: params.data.point.raw.values
```

改造后：

```text
parseCsv -> rows: Record<string,string>[]（键为原始表头）
  -> buildChartGroups -> groups[].series[].points[] (ChartPoint 仅 x/y/rowIndex，rowIndex = rows 数组下标)
    -> createDisplaySeries -> DisplaySeries[]（不含 deviceValue/groupName）
      -> buildChartOption(..., rows) -> data: [[x, y, rowIndex], ...]
        -> tooltip: params.data[2] -> rows[data[2]] -> row[column.rawName]
```
